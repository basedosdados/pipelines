# us_usda_nass — onboarding design

USDA National Agricultural Statistics Service (NASS) QuickStats: crop and
livestock production, yields, acreage, prices received, stocks/inventory, and the
quinquennial Census of Agriculture, by state, county, agricultural district and
commodity. Curated, robustness-first (see `code/SEED_EXCLUSIONS.md`).

Not to be confused with `world_usda_agriculture` (prod), which is the Foreign
Agricultural Service PSD international supply-and-distribution product — a
different thing, referenced in the descriptions and left untouched.

## Source

The 5 QuickStats bulk sector files at <https://www.nass.usda.gov/datasets/>
(`qs.{animals_products,crops,demographics,economics,environmental}_YYYYMMDD.txt.gz`,
~2.5 GB compressed). Together they are the entire QuickStats database:
tab-separated, 39 UPPERCASE columns, `SOURCE_DESC ∈ {CENSUS, SURVEY}`. Both output
tables are a `SOURCE_DESC` filter on the same files. The QuickStats API
(<https://quickstats.nass.usda.gov/api>, free key) is the incremental source but
is **not** used for the bulk load — paging it by commodity-year is the fragile
surface that sank the earlier attempt.

## Tables

Split by geography grain (one grain per table, per-grain schema — no
`geography_level` column, no null geo columns). All LONG, year-partitioned.

- `survey_national`, `survey_state`, `survey_agricultural_district`,
  `survey_county` — `SOURCE_DESC = SURVEY`.
- `census_of_agriculture_national`, `census_of_agriculture_state`,
  `census_of_agriculture_county` — `SOURCE_DESC = CENSUS` (census has no
  agricultural-district grain in QuickStats).
- `dicionario` — `value_suppression_flag` code → label (shared).

Each table reads its own all-STRING staging table; models are generated by
`code/build_dbt_models.py` from the architecture CSVs, and `schema.yml` by
`code/build_schema_yml.py`.

Only `value` (FLOAT64) and `coefficient_of_variation` (FLOAT64) are numeric;
every dimension/code column is STRING. `value` carries **no** column-level
`measurement_unit` — the unit varies per row and lives in the `unit` column.
Value parsing (strip thousands-commas, map `(D)`/`(Z)`/… → NULL + a flag) happens
in Python cleaning, not dbt, because `safe_cast('21,000' as float64)` yields NULL.

## Code (DRY)

- `pipelines/datasets/us_usda_nass/utils.py` — pure transform (download, stream,
  filter, all-STRING parquet). No Prefect imports.
- `pipelines/datasets/us_usda_nass/{constants,tasks,flows}.py` — the recurring
  Prefect 3 pipeline; imports the transform from `utils.py`.
- `models/us_usda_nass/code/clean.py` — one-shot bootstrap; imports the same
  transform.
- `models/us_usda_nass/code/upload.py` — one-shot BigQuery upload (bd.Table,
  all-STRING, dev/prod).
- `models/us_usda_nass/code/build_architecture.py` — emits the architecture CSVs
  (schema source of truth).

## Scratch and cleanup

Raw downloads and cleaned parquet live under `~/Downloads/us_usda_nass_data/`
(never Dropbox/repo). Delete it as the final onboarding step.

## Pipeline

Annual bulk refresh, `dump_mode="overwrite"` (files ship full history). AllFree
coverage on both tables (BD Pro deferred). Run all tables, then test all tables
(the fact tables' `custom_dictionary_coverage` test references the dicionario).
`job_variables` uses `memory_limit` (bare `memory` is silently ignored). Verify a
manual dev run before arming. Follow-up: a load-time-based poll for true
continuous (intra-year) refresh — the v1 poll is year-granularity.

## Measured seed volumes (2026-09-14 dry-count)

crops SURVEY 8.53M (COUNTY 7.03M) + CENSUS 1.74M ≈ 10.3M; animals_products SURVEY
0.42M + CENSUS 1.47M ≈ 1.9M. Total across the 5 files ≈ 13–15M rows across the two
fact tables — bounded and tractable.
